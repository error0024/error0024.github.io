Hash-based signatures are a promising post-quantum option for Bitcoin, since their security relies only on properties of hash functions, which Bitcoin already depends on. We survey these schemes from basic building blocks up to SPHINCS+ and its variants, and study parameter choices suited to Bitcoin. Using recent optimizations and a lower bound on the number of signatures per public key, we obtain significant size reductions compared to standardized SPHINCS+ (SLH-DSA). We release scripts for reproducing our parameter selection and discuss open questions around key derivation, multi-signatures, and threshold signatures.
